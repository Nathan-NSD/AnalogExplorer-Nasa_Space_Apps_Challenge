# AnalogExplorer

**Where on Earth to rehearse the Moon and Mars, dimension by dimension, and what Earth cannot reproduce.**

NASA Space Apps Challenge 2026 — challenge *Identify Earth Locations that Analog the Permanent Moon Base Locations
and Mars*.

- **Live app:** https://aex-spaceapps.streamlit.app/
- **Method:** [docs/method.md](docs/method.md) · **Data and licences:** [docs/data.md](docs/data.md) ·
  **Written field atlas:** [docs/atlas.md](docs/atlas.md)

## What it does

AnalogExplorer compares **23,039 land tiles of the Earth** (1° × 1°, about 110 km) with **7 lunar and Martian
targets**: the Shackleton crater region and the Malapert massif at the lunar south pole, the Mare Tranquillitatis
pit, and Jezero crater, Gale crater, Arcadia Planitia and Oxia Planum on Mars.

Each comparison covers **10 variables in 5 dimensions** (topography, thermal, water and ice, illumination,
surface cover), measured with the same physics on the three worlds from open NASA, ESA and partner data.

For a chosen target and mission (rover mobility, solar panels, drilling and resource use, habitat), the app:
- ranks the **best distinct Earth sites** and shows, variable by variable, where each analogy holds and where it
  breaks;
- finds the **set of 2 to 3 sites** that together cover the target best, since no single place reproduces
  another world;
- highlights **under-studied sites**, far from the analogs already used by space agencies;
- measures the **robustness** of each result when the mission weights change;
- **zooms** into each site to find the ~11 km sub-area whose terrain matches best;
- reports **what Earth cannot reproduce** (gravity, vacuum, radiation, and conditions no place on Earth reaches),
  with figures, and exports a **site sheet**;
- answers the **reverse question**: which world does a given place on Earth resemble?

## How it works

Every tile and every target is described by the distribution (19 quantiles) of each variable. The gap between a
site and a target is the Wasserstein distance between distributions, read in units of the typical gap between two
places on Earth. Variables that no place on Earth can match leave the score and go to the limits report. The
score is a weighted geometric mean, so a good result on one dimension cannot hide a poor one. Full description,
formulas and references: [docs/method.md](docs/method.md); the app's home page shows the same steps.

## Results, stated honestly

- No place on Earth reproduces the lunar day-night temperature amplitude or minimum temperature, nor the
  diurnal amplitude of Mars: these conditions are reported, not ranked.
- A **credibility check**, fixed before looking at the results, asks whether analogs known from the literature
  rank better than random places on the properties they are known for. It **passes for the four Martian targets**
  and **fails for the three lunar targets**: the lunar training sites are much smoother than the lunar poles, and
  often smaller than a tile. These results are shown as they are.
- Results for every target, with the best sites and their limits: [docs/atlas.md](docs/atlas.md), generated by
  rules from the dataset (`python -m src.report --atlas docs/atlas.md`).

## Data

Earth: NASA POWER (climate), Copernicus DEM GLO-90 (relief), ESA WorldCover and SCAR Antarctic Digital Database
(bare ground). Moon: LRO LOLA and Diviner (NASA PDS), NASA PGDA polar illumination. Mars: MGS MOLA (NASA PDS) and
the Mars Climate Database (LMD, with ESA and CNES). Place names: Natural Earth. Every source, its licence and its
required attribution: [docs/data.md](docs/data.md) §2.

The processed dataset (`data/processed/real_v1/`, ~16 MB) is included, so the app runs without downloading
anything. It never shows invented data.

## Run it locally

Python 3.12 or later:

```bash
pip install -r requirements.txt
streamlit run src/app.py
```

Tests and lint (`requirements-dev.txt` adds them, with the tools that rebuild the dataset):

```bash
pip install -r requirements-dev.txt
python -m pytest -q
python -m ruff check .
```

Rebuild the dataset from the open sources (about one hour the first time, no account needed; Python ≥ 3.14):

```bash
python -m src.data_prep --real
```

## Repository

```
├── src/
│   ├── config.py        # variables, mission profiles, thresholds, sourced catalogues
│   ├── sources.py       # readers of the open data (NASA POWER, Copernicus, PDS, PGDA, MCD, WorldCover, SCAR)
│   ├── data_prep.py     # offline construction of the dataset
│   ├── landcover.py     # bare-ground variable (WorldCover and SCAR rock outcrops)
│   ├── math_engine.py   # pure calculation: similarity, score, distinct sites, robustness, ensemble, credibility
│   ├── analysis.py      # the engine applied to a dataset (ranking, ensemble, zoom, atlas)
│   ├── places.py        # place name of each tile (Natural Earth), display only
│   ├── report.py        # limits report, site sheet and written atlas (rules, no language model)
│   ├── charts.py        # Plotly figures
│   └── app.py           # Streamlit application
├── tests/               # pytest, one file per module, no network needed
├── data/processed/real_v1/   # dataset read by the app
└── docs/                # method, data and written atlas
```

## Use of AI

This project was built with the help of an AI assistant, used for debugging and testing, for documentation and translation, for searching the
literature and data sources, and for helping design the demo slide. The idea, the scientific
method and its choices, and the validation of every result are the team's. The application
itself contains no machine learning or language model: its rankings, limits report, site
sheets and written atlas are computed by explicit rules from open data.
